# Shipped levels

`places_demo.json` and the generated `model_zoo.json` are the two levels bundled
with the game. Both are discovered at startup, appear in the Level Select menu,
and are packaged by `tools/package.sh`. Boot straight into one with
`PLACES_LEVEL=places_demo` or `PLACES_LEVEL=model_zoo` (a bundled level shows
its `id`, the display name works in the menu).

`assets/levels/` is the shipped-level directory: every `*.json` here is
packaged. Nothing here is hard-coded, so adding a file adds a menu entry and
removing one removes it. Drop-in user levels live in `levels/` at the repository
root and are discovered alongside the demo without being packaged;
`tests/fixtures/levels/` holds the engine regression fixtures and is never
packaged.

## The shipped levels

| id | name | what it is |
| --- | --- | --- |
| `places_demo` | Places Demo | **The showcase.** One continuous route through everything the project does: office → doorways and windows → red stair hall → empty pool → two steps up → quiet corridor → Home archway, living area and upper balcony. Start here. |
| `model_zoo` | Model Zoo | **The catalogue showroom.** A large, well-lit pool hall that displays every registered placeable model at least once, plus the pose, route, switch, floating-prop, sign and mount demonstrations. Generated by `tools/levels/build_model_zoo.py`; edit the generator, never the JSON. |

### Regenerating the Model Zoo

```sh
python3 tools/levels/build_model_zoo.py              # write assets/levels/model_zoo.json
python3 tools/levels/build_model_zoo.py --check      # fail if the file is stale
python3 tools/levels/build_model_zoo.py --stats      # coverage and layout summary
python3 tools/levels/build_model_zoo.py --workers 8  # bounded inspection workers
```

The tool reads `assets/catalog.json`, inspects each model's real bounds and
animation envelope (cached under `cache/`, invalidated per model by size and
mtime), lays the displays out deterministically and writes one canonical level.
Adding a catalogue entry adds a display; removing one removes it; no other
instance is renumbered. Serial and parallel runs are byte-identical.

## Capacity fixtures

`tests/fixtures/levels/capacity_sparse.json` and `capacity_dense.json` are the
generated stress fixtures for the raised level limits. They are regenerated by
`tools/levels/build_capacity_fixtures.py` (with a `--check` mode) and are the
witness set for the far-from-origin and dense-instance contracts. They are not
packaged and do not appear in the Level Select menu; run one with
`./target/release/places --check-geometry --level tests/fixtures/levels/capacity_dense.json`
or temporarily copy it into `levels/` to boot it.

## Regression fixtures

The fixtures live in `tests/fixtures/levels/`, outside the shipped content, so
they do not appear in a packaged game's Level Select menu. They are
load-bearing: each one is named by an automated test or a documented manual
check.

| id | name | what depends on it |
| --- | --- | --- |
| `test_room` | Test Room | The minimal single-room sample with a door and a window, used by the loader and renderer round-trip tests. |
| `prop_showcase` | Prop Showcase (dev) | `test_showcase_level_collision_matches_the_solid_flags` and `the_showcase_level_renders_every_core_prop_with_real_geometry`. |
| `prop_stress` | Prop Stress Test (dev) | `the_stress_level_batches_repeats_into_one_draw_per_model_and_cell` — ~150 repeated placements across nine models. |
| `capacity_sparse` | Capacity: Sparse World (dev) | The `zoo_audit` far-from-origin contract: four islands at ±2 km with fixtures, a trigger, a route and a floating prop. |
| `capacity_dense` | Capacity: Dense Content (dev) | The `zoo_audit` scale contract: 5000+ placements over every registered model, 100+ fixtures and 16+ routed entities. |
| `pool_showcase` | Pool Showcase | The Pool-family geometry and collision checks in `src/render/tests.rs` and `tests/test_package.py`. |
| `vertical_diagnostic` | Vertical Diagnostic | The vertical-geometry fixtures: an elevated room reached by a region staircase, a walkable recess and a blocked deep recess, a gable room with eave and ridge fixtures, RGB-lit corners, decals. Used by the loader and renderer geometry tests. |
| `rendering_diagnostic` | Rendering Diagnostic | The decal-sheet coverage test (eight placements covering every decal sheet) and the stain-overlay test. |
| `lighting_isolation` | Lighting Isolation | The whole `src/lighting_isolation.rs` suite (13 cells, one per wall-boundary rule: blocked white light, blocked colour, doorway transmission, window sill and header, two coloured rooms, dark neighbour, interior partition, lit corners, unlit control). The acceptance fixture for wall-boundary lighting isolation. |
| `lighting_diagnostic` | Lighting Diagnostic | `emitted_wall_faces_are_lit_by_the_room_they_open_into` — a wall authored across a room boundary. |
| `home_showcase` | Home Showcase (dev) | The Home theme and every generic architectural piece: four rooms (living room, hall, kitchen, bedroom), a split-level platform reached by a staircase and a ramp, an archway, a knee wall, columns, guardrails, thresholds, baseboards, both hardwoods, carpet, tile and both ceilings. Depended on by `test_validate_accepts_the_home_showcase_fixture`, `test_the_home_showcase_bakes_lightmaps_with_every_surface_vertex_charted`, `test_the_home_showcase_architecture_is_well_formed`, `the_home_showcase_has_no_coincident_architecture_surfaces`, the collision and controller tests, and `tests/test_package.py`'s Home checks. |
| `geometry_broken` | Geometry Broken | The planted-defect fixture for the map geometry checker. |
| `geometry_intentional` | Geometry Intentional | The checker's valid-curves/openings/rotated-frames fixture and its intent-annotation coverage. |
| `invalid/geometry_invalid` | Geometry Invalid | Loader-rejected degenerate curves; in a subdirectory so the level scanner skips it. |

`prop_showcase` and `prop_stress` are **generated**: running
`python3 tools/levels/build_fixture_levels.py` overwrites them; the two
`capacity_*` fixtures are generated by
`python3 tools/levels/build_capacity_fixtures.py`. Change the generator, not the
JSON. Every other fixture is hand-authored and safe to edit directly.

`home_showcase` is the level to boot when working on the Home theme or the
generic architectural pieces. It is a fixture rather than shipped content, so it
does not appear in a packaged game's menu; copy it into `levels/` (the drop-in
directory) when you want it in Level Select:

```sh
cp tests/fixtures/levels/home_showcase.json levels/
PLACES_LEVEL=home_showcase cargo run
```

## Retired shipped levels

The packaged content ships the official demo and the generated Model Zoo.
`level_1`, the three residential levels, the Office and Pool showcases, the
texture diagnostic and the two generated asset demos (`asset_demo`,
`asset_maintained`) are no longer bundled, along with the tests that only
asserted those levels' own design. The demo, the zoo, and any user level, still
resolve the complete catalog, so no asset was removed: every model, texture and
material in `assets/catalog.json` remains available to `Places Demo`, the Model
Zoo, the engine and user-created levels.

The Model Zoo supersedes the old hand-built showcase levels as the place to find
"where is every asset": it is generated from the catalog, so it cannot fall
behind it.
