# Entities

Entity assets are characters and creatures. An entity is an **asset class**, not
an environment theme and not a prop: there is no `entities` theme anywhere in the
catalog.

```
entities/
  mannequin/
    model/mannequin.glb
    textures/concrete_grey_01.png     source sheet, embedded into the GLB
  rat/
    model/rat.glb
    textures/rat_fur_01.png
  skeleton/
    model/skeleton.glb
    textures/bone_01.png
  spooner-man/
    model/spooner-man.glb
```

Built by the entity toolkit (`tools/entities/`): rigged GLBs with a real skin,
named clips and per-clip loop/reference-speed metadata.

* Logical ids: `spooner-man`, `mannequin`, `rat`, `skeleton` (existing levels
  keep referencing `spooner-man` unchanged).
* `asset_class: entity`, `asset_type: entity`, `entity_type: character`.
* No theme: an entity may stand in any environment.

Entities resolve through the same placeable lookup as props, so levels place
them with the ordinary `props` format, and placement, orientation, scale and
appearance are unchanged. At run time the character path claims every placed
skinned model and plays the clip its route or `play_animation` cue names; a
placed entity with no cue follows the player's locomotion snapshot (named
`idle`/`walk`/`run` clips, else the procedural gait, else its first clip).

Each has its own README with the joint list, clip table, placement notes and
measured reference speeds. `spooner-man` is a hand-exported Blender model with
one `cat_rig` skin (26 joints: `root`, `pelvis`, `spine`/`chest`/`neck`/`head`,
four `leg_*` chains and `tail_01`..`tail_08`) and three primitives. Its skin
weights bind every vertex with a deterministic nearest-segment two-bone blend
(the clip tool in `tools/props/` is the reproducible source path), so the paws
deform with the legs.

The remaining entities are generated by the pure-Python entity toolkit
(`tools/entities/`): rigged GLBs with a real skin, named joints and LINEAR
clips, plus `asset.extras.places_entity_clips` metadata recording each clip's
loop flag and the ground speed its stride is authored for.

The Halloween entities (`carved-pumpkin`, `sheet-ghost`, `pumpkin-skeleton`)
were modelled and rigged outside the repository's toolkit and are registered as
ordinary catalogued entities. Their runtime material contracts were authored on
top of the shipped geometry by `tools/entities/author_halloween_assets.py`
(deterministic, `--check`-able): the pumpkin head is a second primitive with a
mild warm emissive factor, and the ghost carries `alphaMode: "BLEND"` plus a
mild cyan emissive factor. The carved pumpkin's `candle_flame` primitive was
already emissive and is left untouched. Geometry, UVs, vertex colours, skins,
inverse bind matrices and every animation channel of these three models are
unchanged by that tool.

The directory is designed to hold future player models, NPCs and creatures as
new subdirectories (`entities/<id>/model/...`) with catalog entries of their
own. Entity gameplay — AI, player-character switching — is deliberately not
part of this architecture yet.

## Forward basis and frame units

Every shipped entity rig faces **world +Z** in its bind pose, measured from the
committed GLBs by node FK: the rat's skull sits at `z = +0.213 m`, its neck at
`z = +0.169 m` and its tail tip at `z = -0.262 m`; the cat's head at
`z = +0.228 m`, its front paw at `z = +0.113 m`, rear paw at `z = -0.132 m`
and tail tip at `z = -0.246 m`. The render path applies no per-asset
orientation correction; `src/gltf/tests.rs` pins the head-leads-tail relation
for both rigs.

World yaw is **radians**, with `0` facing `+Z` (the same unit as the route
runtime's `RouteState::yaw` and the renderer's `Character::set_pose`). The AI
layer stores its yaw in **degrees** and converts exactly once, at its
`EntityFrame` handoff: an agent travelling `+X` emits a frame yaw of about
`+PI/2`, not `90.0`.

Every animation clip is **in place**: it articulates the rig without horizontal
root displacement (the cat's pounce has a vertical pelvis arc only), so the
runtime takes position from the route or AI and never compensates for root
motion.
