# Entities

Entity assets are characters and creatures. An entity is an **asset class**, not
an environment theme and not a prop: there is no `entities` theme anywhere in the
catalog.

```
entities/
  mannequin/
    model/mannequin.glb
    textures/concrete_grey_01.png     source sheet, embedded into the GLB
  rat/
    model/rat.glb
    textures/rat_fur_01.png
  skeleton/
    model/skeleton.glb
    textures/bone_01.png
  spooner-man/
    model/spooner-man.glb
```

Built by the entity toolkit (`tools/entities/`): rigged GLBs with a real skin,
named clips and per-clip loop/reference-speed metadata.

* Logical ids: `spooner-man`, `mannequin`, `rat`, `skeleton` (existing levels
  keep referencing `spooner-man` unchanged).
* `asset_class: entity`, `asset_type: entity`, `entity_type: character`.
* No theme: an entity may stand in any environment.

Entities resolve through the same placeable lookup as props, so levels place
them with the ordinary `props` format, and placement, orientation, scale and
appearance are unchanged. At run time the character path claims every placed
skinned model and plays the clip its route or `play_animation` cue names; a
placed entity with no cue follows the player's locomotion snapshot (named
`idle`/`walk`/`run` clips, else the procedural gait, else its first clip).

## The shipped entities

| id | shape | joints | triangles | clips | source |
| --- | --- | --- | --- | --- | --- |
| `spooner-man` | tuxedo cat, 26-joint `cat_rig` | 26 | 1380 | `idle`, `walk`, `sit_down`, `sit_idle`, `stand_up` | hand-exported Blender model + `tools/props/animate_spooner_man.py` |
| `mannequin` | grey concrete human lay figure, 23 joints | 23 | 1130 | `pose_stand`, `pose_arms_up`, `pose_arms_forward` | `tools/entities/build_mannequin.py` |
| `rat` | rat with four 3-segment legs and a 5-segment tail | 25 | 856 | `idle`, `walk` (0.199 m/s), `run` (0.573 m/s) | `tools/entities/build_rat.py` |
| `skeleton` | articulated human skeleton, 24 joints | 24 | 1352 | `pose_stand`, `pose_sit_floor`, `pose_sit_chair` | `tools/entities/build_skeleton.py` |

Each has its own README with the joint list, clip table, placement notes and
measured reference speeds. `spooner-man` is a hand-exported Blender model with
one `cat_rig` skin (26 joints: `root`, `pelvis`, `spine`/`chest`/`neck`/`head`,
four `leg_*` chains and `tail_01`..`tail_08`) and three primitives. Run 3
repaired the shipped skin weights, which bound the paws to the body chain, with
a deterministic nearest-segment rebind; the clip tool in `tools/props/` is the
reproducible source path.

The run-04 entities are generated by the pure-Python entity toolkit
(`tools/entities/`): rigged GLBs with a real skin, named joints and LINEAR
clips, plus `asset.extras.places_entity_clips` metadata recording each clip's
loop flag and the ground speed its stride is authored for.

The directory is designed to hold future player models, NPCs and creatures as
new subdirectories (`entities/<id>/model/...`) with catalog entries of their
own. Entity gameplay — AI, player-character switching — is deliberately not
part of this architecture yet.
